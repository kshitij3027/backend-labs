# api-rate-limit-qouta-sys — Python dependencies (pinned FastAPI + Redis stack).
#
# Pins are EXACT so image builds are reproducible and offline-friendly. This layer is
# installed before the app source is copied, so it caches once and code changes only
# rebuild the thin source layer on top of it. Everything here resolves to a prebuilt
# manylinux wheel on python:3.11-slim — no C toolchain required.
#
# The defining dependency of this project is Redis. Rate-limit buckets and cumulative
# quota counters MUST live outside the process: two API replicas each holding their own
# in-memory bucket would let a caller spend the limit twice, which is exactly the bug
# this project exists to not have. State is shared, and every read-modify-write against
# it is a server-side Lua script so the check-and-decrement is atomic under concurrency.

# --- Shared state: token buckets + quota counters across replicas ---

# --- Auth: API-key hashing + JWT verification (two accepted credential forms) ---
#
# NO bcrypt here, deliberately. API keys are hashed with HMAC-SHA256 + a server-side pepper —
# stdlib `hmac` and `hashlib`, so there is nothing to pin — and that is a correctness decision
# rather than a convenience one:
#
#   * bcrypt at its default cost is ~250 ms per hash. This project's ENTIRE latency budget for a
#     rate-limit check is 5 ms, and identity resolution runs on every metered request, so bcrypt
#     alone would be 50x the budget before the limiter had done anything.
#   * bcrypt salts every hash individually, which means you cannot LOOK A KEY UP by its digest.
#     Answering "who is this?" would mean bcrypt-comparing the presented key against every stored
#     key in turn — O(n) 250 ms hashes per request. The whole storage design here is a single
#     `apikey:v1:<hmac_sha256_hex>` HASH lookup, which a per-hash salt makes impossible.
#   * A password KDF exists to slow dictionary and offline-search attacks against low-entropy
#     human-chosen secrets. These API keys are 256-bit CSPRNG output: there is no dictionary to
#     try and no search that terminates, so the KDF buys nothing for what it costs.
#
# The pepper lives in the app's environment (API_KEY_PEPPER), never in Redis, so a stolen Redis
# dump on its own yields digests an attacker cannot invert or replay. Rotating the pepper
# invalidates every stored key by construction.
PyJWT==2.9.0
python-multipart==0.0.12   # OAuth2 password-form body parsing for the token endpoint
